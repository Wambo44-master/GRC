### Purpose

This policy ensures that all systems that contain or process electronic Protective Health Information (ePHI) must generate logs that record actions performed, who performed them and where hey were performed. The generated logs must be stored securely, free from tampering and made available to security personnel, based on MaishaBora’s authentication and authorization checks, teams for monitoring, alerting and investigation.

### Scope

This policy applies to all employees, contractors, consultants, and any other workers who have authorized access to Maisha Bora information systems that process, store or transmit electronic Protected Health Information (ePHI). It also applies to any systems involved used by Maisha Bora and relevant in log generation and processing. This includes user logins, access to epHI, configuration changes, permission changes, all access attempts and system events. All submitted logs must be submitted for evaluation and monitoring. These logs will be stored in a tamper proof repository for at least six years as per HIPAA recommendations. The logs generated will be used in real time monitoring, audits and forensic investigations.

**1. Definitions**

●	User Access Review (UAR): The process of verifying and validating user access rights to systems and data.

●	Least Privilege: The security principle that individuals should be granted the minimum level of access necessary to perform their job functions.

●	Privileged Access: Access rights that allow users to perform administrative or specialized duties on IT systems.

●	Electronic Protected Health Information (ePHI): Any identifiable health information that is transmitted or maintained in electronic media as defined under 45 CFR & 160.103.

________________________________________

**2. Policy Statement**

This policy mandates regular reviews of user access rights to ensure they remain appropriate and secure. The reviews will identify any discrepancies or excess privileges that need adjustment to maintain security and compliance with company policies.

*2.1.	 Principle of Least Privilege*: Users shall be granted only the minimum level of access of necessary to perform their job functions.

*2.2.	 Authorization*: All access requests must be approved in writing by the user’s direct manager before access is granted.

*2.3.	 Authentication*: All users must authenticate using multi-factor authentication (MFA) before accessing any system containing ePHI.

*2.4.	 Review*: User access rights shall be reviewed and recertified by managers on a quarterly basis. Access for terminated employees shall be revoked with 24 hours of termination.

*2.5.	 Log generation*: All systems used in the containment and processing ePHI in Maisha Bora, including: user logins, ePHI access, configuration changes, permission changes, all access attempts and system events; must generate logs that record the action performed, the actor and the action’s location.

*2.6.	 Monitoring*: All logs generated by MaishaBora’s systems must be made available to authorized security teams for continuous monitoring also be used as per MaishaBora’s mission.

*2.7.	 Log Evaluation*: All logs generated by MaishaBora’s systems which contain and process ePHI must be submitted for evaluation by authorized IT security teams.

*2.8.	 Log Storage*: Logs generated by MaishaBora’s systems will be stored for at least 6 years per HIPAA recommendations. Maisha Bora logs containing and processing ePHI will be stored securely.  

*2.9.	 Technical Enforcement*: Access controls shall be enforced using:

•	AWS IAM for identity and permission management

•	AWS KMS for encryption key management and access control to encrypted data

•	AWS Config for continuous recording and evaluations of resource configuration

•	AWS CloudWatch for log monitoring and evaluation.

•	AWS CloudTrail for API records within MaishaBora’s AWS environments.

•	AWS S3 for immutable log storage and audit trails.

•	AWS GuardDuty for continuous monitoring, threat detection and alert logging.

•	AWS Security Hub to aggregate findings from AWS Config, AWS CloudWatch and AWS CloudTrail into a single dashboard.

**3. Responsibilities**

●	IT Security Team: Lead and coordinate the log generation, monitoring and evaluation, including preparation, execution, and follow-up actions.

●	Department Managers: Review and validate access rights for their respective teams, ensuring accuracy and appropriateness.

●	Employees: Use and access only systems they are authorized to use.

**4. Log generation, monitoring process**

*4.1 Scheduling and Planning*

●	Log generation and monitoring must be conducted continuously.

●	The IT Security Team will set up log generation and evaluation systems allowing access based on MaishaBora’s authorization and authentication checks.

*4.2. Log generation and monitoring*

●	System and Application List: Compile a comprehensive list of all systems and applications that contain and 

●	User Access Report: Generate current access rights reports from all systems and applications.

●	Review and Validation:

○	Department Managers review access rights for appropriateness based on current job functions and responsibilities.

○	IT Security reviews logs for real time monitoring, alerts, audits and forensic investigations as well as for compliance with least privilege and security best practices.

○	Employees only access the systems on which they are authorized.

*4.3 Issues Identification*

●	Document any unauthorized, outdated, or excessive access rights found during the review.

●	Highlight any discrepancies between recorded and actual access levels.

*4.4 Remediation Actions*

●	Remove or adjust access rights that are not justified during the review process.

●	Update records to reflect changes made during the review.

*4.5 Documentation and Reporting*

●	Maintain detailed records of the review process, including changes made, persons involved in the review, and any issues identified.

●	Prepare a summary report of the review outcomes for management and audit purposes.

**5. Exception Handling**

●	Exceptions must be reviewed continuously to ensure they are still valid.
